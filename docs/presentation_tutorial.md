# 発表デモチュートリアル

## 起動

Android StudioのRun ConfigurationのAdditional run argsに以下を追加します。

```text
--dart-define=ZOOSTUDY_PRESENTATION=true
```

A・Bそれぞれ別のスマートフォンで起動してください。
既存の役割選択画面を発表用のログインとして使います。認証・通信・永続保存は行いません。
Aでは「先生はこちら」→「確定」、Bでは「生徒はこちら」→「確定」→「生徒デモをはじめる」を選びます。
ログイン後に同じ端末で先生役・生徒役を交代する手順はありません。
先生は既存の課題作成・詳細・学習記録・アドバイス画面をそのまま使用します。
既存の実アカウントで先生ログインしている場合は、その先生画面を使用しても構いません。Bにはあらかじめ用意した課題と結果を表示します。

PowerShellで実機を指定する場合：

```powershell
C:\flutter\bin\flutter.bat devices
C:\flutter\bin\flutter.bat run -d <端末ID> --dart-define=ZOOSTUDY_PRESENTATION=true
```

フラグ変更後は停止して再起動します。`--release` でも明示的なデモ起動に対応します。
Firebase・端末保存データを開く前に発表用ログインへ入ります。
通常の生徒ログイン後も「その他 → 発表デモチュートリアル」からB用のデモを開始できます。
以前の `ZOOSTUDY_PRESENTATION_ROLE=teacher` 指定が残っていても、ログイン画面で役割を選択します。

## 発表ルート

実通信は行いません。発表者がA・Bの操作順を合わせます。

| 順番 | A：先生のスマートフォン | B：生徒のスマートフォン |
| --- | --- | --- |
| 1 | 先生としてログイン。既存の「課題を作成」→「課題を配布する」 | 生徒としてログイン。初期資金3,000コイン |
| 2 | 配布済み課題を提示 | 下の「学習」→「課題提出」。同じ課題が最初から一覧にある |
| 3 | Bの提出を待つ | 「詳細・回答する」→既定の回答で「課題を提出する」。＋30コイン |
| 4 | 「提出内容を確認」→「内容を確認して承認」 | 確認待ちを表示した後、課題詳細・一覧から戻り、学習メニューで待つ |
| 5 | 「生徒の学習記録」→「アドバイス案を作成」→内容を確認して送信 | Aの操作完了を待つ |
| 6 | 承認・送信済みを提示 | 「課題提出」を開き直す。用意済みの承認結果を受信した状態に切り替わり、＋70コイン |
| 7 | 操作不要 | 課題詳細の「承認済み」と先生のコメントを確認。学習記録でもアドバイスを読める |
| 8 | 操作不要 | ホームへ戻り、ショップでウサギ購入→囲いに配置 |
| 9 | 操作不要 | 池を購入・配置→キツネ・研究所を購入→研究所を配置→炎狐へ進化 |
| 10 | 操作不要 | 炎狐を囲いへ→図鑑→「育った園を見る」で完成景 |

Bには課題の作成・配布・承認ボタンを置きません。デモ用Repositoryも公開の配布・承認操作を拒否します。
課題はBの開始時に配布済みデータとして用意します。提出後にBで課題メニューを開き直すことを、準備済みのA側の応答を読み込むタイミングとして使います。
Aを操作せずBを開き直しても実通信では検証できないため、必ず上の順序で発表してください。Bの提出直後はまだ確認待ちであり、時間経過だけでは承認しません。

課題名・内容・回答例・アドバイスは `PresentationScenario` の共通データです。
先生のデモ用データでは配布後に提出の回答例を用意するため、Bの提出演技が終わってからAで提出内容を開きます。
先生の入力やBの回答を編集しても、別端末には反映されません。発表では既定の内容を使用してください。

## ゲーム部分の操作

購入・配置・進化は実際のボタンを金色の枠でハイライトして誘導し、確定した結果で手順が進みます。
最初から3,000コインを持ち、途中の資金受領操作はありません。
柵をタップすると購入済み動物を選んで配置でき、配置済み研究所をタップすると既存の研究画面が開きます。

動物一覧は手順に合わせて初期ページを切り替えます。

- ウサギの配置：ウサギのページ。
- 進化後の炎狐の配置：炎狐のページ。
- 最後の図鑑紹介：炎狐のページ。
- それ以外・通常プレイ：従来どおり最初のページ。

左右のページ移動で他の動物も引き続き閲覧できます。
施設配置はマップを常時表示し、画面に合わせて全体を縮小します。縦画面はマップと下部操作欄、横画面は左右に分けます。
通常サイズでは確定・キャンセルも初めから画面内に収めます。文字を大きくして操作欄が入り切らない場合は、その欄だけスクロールでき、マップは隠れません。
配置枠を掴んだ操作はページスクロールやカメラより優先され、位置はタイル単位で追従します。

案内は左下の旧木製枠に表示し、通常の「最初の仲間を迎えよう」はデモ中に表示しません。
再開・説明・案内表示切り替え・終了は「その他」にまとめています。
通常通知は上から約2.4秒、デモ通知は左下の木枠内へ一時表示します。
完成景は全画面で締めくくります。

## 説明上の区別

- A・Bは独立したローカルデータです。実通信・同期・本物のログイン認証の実演ではありません。
- Bの提出30・承認結果70は一度ずつ加算します。メニューを何度開いても二重付与しません。
- 初期資金3,000コインと無料4×4囲いはデモ設定です。通常アカウントの残高は変更しません。
- 最終景の27種類・4区画・施設は完成イメージで、報酬履歴や残高を追加しません。
- Firebase・既存の端末保存は変更せず、終了・初期化で消えます。追加パッケージもありません。

初期3,000＋報酬100−ウサギ100−池200−キツネ250−研究所400−炎狐500＝残高1,650コインです。

## 実装の範囲・変更ファイル

- `lib/features/game/demo/presentation_repository.dart`：Bの配布済み課題・受信結果・アドバイス、配布／承認操作の拒否。
- `lib/features/game/demo/demo_tutorial_controller.dart`：既存課題メニューを使う生徒専用の進行。
- `lib/features/game/demo/demo_tutorial_screen.dart`：既存の役割選択による発表用ログイン。
- `lib/features/game/demo/demo_guide_panel.dart`：単一端末での回答・承認ダイアログを廃止。
- `lib/features/zoo/presentation/zoo_screen.dart`：課題メニューの受信演出、手順別の図鑑ページ。
- `lib/features/zoo/presentation/zoo_chrome.dart`・`lib/features/study/student_learning_menu.dart`：学習・課題提出の誘導表示。
- `lib/features/zoo/presentation/facility_placement_screen.dart`：マップと操作欄を分けた配置エディタ。
- `test/features/game/demo/demo_tutorial_test.dart`：A・Bの独立性、Bの権限制限、報酬と購入・配置。
- `test/features/game/demo/demo_tutorial_ui_test.dart`：実際の課題メニュー・回答画面から完成景までの操作。
- `test/features/game/demo/demo_bootstrap_test.dart`：ログイン後のA／B別起動。
- `test/features/zoo/facility_placement_ui_test.dart`：マップ全体と確定・キャンセルの表示、ドラッグ。
- `README.md`・本書：発表手順。
