# 保存機能の試し方

## 端末内保存：設定なしですぐ確認

    flutter pub get
    flutter run

通常のデバッグ起動は ZOOSTUDY_STORAGE=local です。課題、回答、提出状態、報酬、残高、動物・施設、購入履歴を端末に保存し、アプリを完全終了しても復元します。プラグインを追加したため、初回はホットリロードではなくアプリを停止して再起動してください。

先生・生徒が1つのデモデータを共有します。起動のたびに先生・生徒の選択画面を表示します。役割を変更してテストするときはアプリを停止して再実行してください。以前保存した役割は起動時に使用しません。課題・回答などの保存データはそのまま残ります。課題作成、回答、確認コメントの入力途中も端末に下書き保存します。別端末への同期はありません。保存に失敗した場合は画面に表示し、壊れた既存データを空データで自動上書きしません。

SharedPreferencesはデモと下書きだけに利用します。OSやブラウザーのデータ消去、異常終了時の完全な耐久性、暗号化、改ざん防止は保証しません。本番の残高・提出データの正本はFirestoreです。

## Firebaseエミュレーター：本番プロジェクト不要

Node.js 20とJava 21以上が必要です。WindowsではAndroid Studio付属Javaをスクリプトが検出します。

    cd functions
    npm ci
    cd ..
    .\scripts\start-emulators.ps1

別のターミナルで実行します。

    .\scripts\seed-emulator.ps1
    flutter run --dart-define=ZOOSTUDY_STORAGE=emulator

Webで試す場合は次のコマンドです。

    flutter run -d chrome --dart-define=ZOOSTUDY_STORAGE=emulator

Androidエミュレーターは10.0.2.2、Webは127.0.0.1に接続します。Auth:9099、Firestore:8080、Functions:5001、Storage:9199、管理UI:4000を使用します。Android実機では別途ポート転送などが必要です。エミュレーターは外部公開しないでください。

架空のエミュレーター専用アカウント：

| 役割 | メール | パスワード |
|---|---|---|
| 先生 | teacher@example.test | ZooStudyDemo123! |
| 生徒A | student@example.test | ZooStudyDemo123! |
| 生徒B | student2@example.test | ZooStudyDemo123! |

固定パスワードはエミュレーター専用です。seedスクリプトはdemo-*プロジェクトとループバック接続以外では停止します。

1. 先生でログインし、「課題」から作成・配布。
2. 生徒でログインし、「課題」からテキスト回答または画像・PDFを提出。本人の残高だけ30コイン増加。
3. 先生の課題画面で生徒を選び、承認または再提出依頼。
4. 承認で70コイン追加。再提出では提出報酬を再付与しません。
5. 生徒はショップで100コインのウサギを購入できます。
6. ログインし直してもサーバーの保存情報を取得できます。

同じブラウザープロファイルではAuthのログインがタブ間で共有されます。同時に先生・生徒を開くなら別のブラウザープロファイルを使います。画面でアカウントを切り替える場合は「その他 → ログアウト」を利用してください。

終了はCtrl+C。起動スクリプトは終了時に.firebase/demo-exportへ保存し、次回起動で読み込みます。強制終了・電源断では終了時保存ができない場合があります。

## 本番Firebase接続の準備（今回は未公開）

config/firebase.example.jsonをconfig/firebase.local.jsonへコピーし、対象プラットフォームのFirebaseクライアント設定とFIREBASE_STORAGE_BUCKETを記入します。Functionsにも同じバケット名をZOOSTUDY_STORAGE_BUCKETとして設定し、Cloud Storageを有効化してstorage.rulesを配備してください。local.jsonはGit対象外です。サービスアカウント秘密鍵をアプリ・Gitへ入れてはいけません。

    flutter run --dart-define-from-file=config/firebase.local.json

Firebaseプロジェクト、Email/Password認証、事前登録したユーザーと所属情報が必要です。自己登録・招待・管理者UIは未実装です。このMVPは1アカウント1クラス、1クラス100人までです。

管理側で以下を用意します。クライアントには直接書き込みを許可しません。

- users/{uid}: organizationId, classId, displayName
- classMemberships/{classId_uid}: organizationId, classId, userId, displayName, role
- classes/{classId}: organizationId

Functionsはasia-northeast1、Node.js 20です。firebase.json、firestore.rules、firestore.indexes.json、storage.rules、functions/を用意しています。今回は本番プロジェクトの作成・デプロイ・課金設定を行っていません。サービス有効化・必要な課金プラン・公開承認を確認して別途配備してください。

認証はFirebase Authentication、読み取り制限はFirestore Security Rules、提出・確認・購入はCallable Functions内でも所属・役割を検証します。報酬と残高はFirestoreトランザクションで更新します。価格はサーバーのカタログから取得し、作成・更新時刻はサーバーで確定します。操作キーを保存するため、応答を受け取れず再送しても二重処理せず、古い提出の再送で状態を戻しません。確認時には回答のバージョンを照合して誤承認を防ぎます。

公開前にはApp Check、監視・利用量管理、保存・削除方針、アカウント無効化、バックアップ・復旧を実環境で確認してください。

## 画像・PDFで提出

生徒の課題詳細で「フォトから選ぶ」から写真を選ぶか、「画像・PDFを添付」から端末のファイルを選び、「提出する」を押します。JPEG・PNG・PDFに対応し、1提出につき最大3ファイル、各10MiBまでです。添付があれば回答欄は空でも提出できます。先生は提出一覧からファイル名を押して画像を拡大表示、PDFをページ閲覧し、承認・再提出依頼を行えます。再提出時は添付の追加・削除ができます。

端末内モードではファイル本体をアプリのサポート領域（WebはIndexedDB）、ファイル名などを既存の保存領域に保存します。ファイル選択後、提出前の下書きも復元します。アプリ削除やブラウザーのサイトデータ消去では添付も失われます。

Firebaseモードでは非公開のCloud Storageに保存します。本人と同じクラスの先生のみ閲覧可能です。サーバーがファイルの存在・所有者・サイズ・形式・内容のハッシュを確認してから提出と報酬を確定します。公開ダウンロードURLは発行しません。添付を選択した時点でアップロードするため、提出を中止したファイルや下書きから削除したファイルは残ります。不要ファイルの定期削除は未実装で、本番運用前に保存期間を決めてください。

添付の保存・復元、ファイルのみの提出、画像プレビュー、再提出時の報酬重複防止、不正ファイルと他人のファイルの拒否もテスト対象です。

Androidの「フォトから選ぶ」はインストール済みのGoogleフォトを直接開きます。Googleフォトがない端末では写真・ギャラリーアプリの選択を表示します。Androidでは写真を1枚ずつ追加し、合計3件まで添付できます。PDFなどは「画像・PDFを添付」から選択してください。

## 勉強モード（Android）

生徒の「学習 → 勉強モード」で科目を選び、説明を確認して「確認してカメラを準備」を押します。初回はYOLO26sの公式モデルを取得するためインターネット接続が必要です。カメラを許可し、顔または教材と手元を映してください。3回連続して同じ映り方を確認すると方式を自動選択します。両方が映る場合は教材側を優先し、暗い・誰も映っていないなど判別できない場合は選択を保留します。前後カメラの切り替えと映り方の再確認ができます。

「勉強を開始」後はプレビューを隠し「勉強中」を表示し、自動消灯を抑止します。終了・画面外への移動時には解除します。3秒間隔で端末内の判定処理を呼び、撮影に使った一時ファイルは各解析の終了時に削除します。通常の画像メモリも保存・送信しません。音声収録は無効です。画面外へ移動・ロックした間はカメラを解放し、記録上も停止時間として分離します。再開後は観測・初期姿勢を取り直します。顔の追跡が切れた場合も、単独の顔を連続確認してから再校正し、それまでは判定保留です。個人識別はしません。

「終了して保存」で科目、開始日時、経過時間、停止時間、顔/手元の方式、判定別時間、観測回数を保存します。顔の姿勢継続と手元の学習推定は別の項目で、集中度・理解度として合算しません。判定が8秒以上更新されない場合は自動的に保留へ移り、未観測時間を学習推定時間にしません。最大24時間で区切ります。コインの付与条件は下記「勉強モードのコイン（報酬ポリシーv2）」を参照してください。

15秒ごとと画面外への移動時に、アカウント単位の端末内チェックポイントを保存します。異常終了した場合は次回「勉強モード」または「学習記録」を開いた際に、中断した記録として保存済み時点まで復元します。保存間隔内の未保存分は失われる場合があります。閉じていた時間は追加しません。終了時の未送信データは端末に残し、再試行時は同じIDで保存して重複を防ぎます。

生徒は「学習 → 学習記録」、先生は「課題 → 生徒の学習記録」から確認できます。端末内モードは従来通り同じ端末のデモ生徒を共有し、Firebaseモードは本人と同じクラスの先生だけが読めます。FirebaseのstudySessionsにはCallable FunctionsのsaveStudySessionを通して保存し、生徒名・所属はサーバー側で確定します。記録は端末からの観測報告で、真正な学習をサーバーが証明するものではありません。

先生向け生成AIアドバイスのAPI接続はまだ実装していません。後から記録集計を使えるようdetectorVersion付きで保存します。顔画像・OCRの認識本文・座標は記録へ含めません。今回はAndroidの既存study_detectorを移植しており、iOS/Webでカメラ判定は開始できません。Webからの課題操作・学習記録閲覧は可能です。本番利用にはFunctions・Firestore Rules・インデックスの配備が別途必要です。今回はデプロイしていません。

顔検出プラグインの要件に合わせ、iOSプロジェクトの最低対象を15.5へ変更しています。iOSのビルド・動作確認はWindows環境では実施していません。

## 勉強モードのコイン（報酬ポリシーv2）

同じ日本時間の日のコイン対象時間を合算し、2分につき1コイン、1日最大30コインを終了・中断記録の保存時に確定します。2分未満の端数も同日の次回へ持ち越し、日付は日本時間0時に切り替えます。日付をまたぐ回は対象区間を日ごとに分割します。過去のv1記録は対象時間を保存していないため遡及付与しません。

誤検出で読書・思考を不利にしないため、教材あり（手の動きなしも含む）、手元の学習推定、顔の姿勢継続・姿勢確認中、端末の用途未確認（調べ学習を含む可能性）の時間を対象にします。開始時も教材が安定して見えていれば手の検出なしで手元モードを自動選択します。教材と顔の両方が映る場合は教材側を優先します。実際の学習や集中を証明するものではなく、放置された教材や動画視聴を完全に区別できる仕様ではありません。

一時的な見失いは最後の有効な観測から最大30秒だけ継続扱いにします。毎回の観測結果の有効期限は8秒です。撮影・解析エラー、古い結果、画面外では即時に対象時間の計測を止め、過去の観測からの猶予もリセットします。勉強中に今回の対象時間と計測・保留の状態を表示し、「カメラの映り方を確認」でプレビューを任意に開けます。既に計測した時間の減点はありません。

v2の記録にはrewardPolicyVersionと日別rewardMsByDayを追加し、確認画面には獲得コインを表示します。ローカルでは記録・日別集計・残高を同じ保存状態へまとめて書きます。FirebaseではsaveStudySession内のトランザクションでstudySessions・studyDailyRewards・残高を更新し、同じ記録の再送、同日並行保存でも重複付与・日別上限超過を防ぎます。入力日時・日別時間・観測回数も検証しますが、報告は端末由来であり、改造クライアントに対する実学習の証明ではありません。本番Functionsへの配備は行っていません。


## 学習アドバイス（試作）
先生の「課題 → 生徒の学習記録」で生徒を選択し「アドバイス案を作成」。振り返り・先生への確認ポイント・生徒向け文章案を確認し、編集して「確認して生徒へ送る」と本人の学習記録に表示します。送信済み文章は変更不可。同一送信の再試行は重複しません。承認前は生徒には見えません。

端末内デモは定型文プレビューで、外部AIは使用しません。下書きと承認した文章は既存のstudy-state内に保存します。先生・生徒が同じ端末データを使うデモで、権限の隔離はFirebaseモードで行います。現状デモの集計は利用回数・利用時間で、科目別と提出状況を含むAI集計はFirebase側です。

FirebaseはgenerateStudyAdvice / publishStudyAdviceを使います。studyAdviceDraftsは同じクラスの先生だけが読めます。承認した文章のみstudyAdviceへコピーし本人と同クラスの先生に公開。直接書き込みは禁止。サーバーで所属・先生権限・対象生徒・文字数を検証します。生成の再送には同じrequestIdを使用し、同じ先生・生徒の連続生成は60秒制限。失敗時も1分待って再試行。最大1000件/各コレクションの試作上限です。

直近7日とその前7日の学習モード利用回数・停止時間を除いた時間・科目別時間、直近7日に締切の配布済み課題数と現時点の提出数をサーバーで集計。氏名・ユーザーID・画像・動画・OCR・姿勢判定・自由記述の提出回答はAIへ送りません。科目名のみ最大100文字のデータとして扱います。集中度・理解度・性格などの推測禁止を指示し、形式不正・拒否・途中終了は下書きとして保存しません。内容の妥当性は先生が確認してください。

外部AI接続にはGemini APIを使用（サーバーREST、依存パッケージ追加なし）。Firebase CLIでSTUDY_ADVICE_API_KEYをSecret Managerに登録し、functions/.env.<プロジェクトID>へSTUDY_ADVICE_MODEL=<利用可能なモデルID>を設定後、FunctionsとFirestoreルールを配備する必要があります。キーをアプリやGitへ入れないでください。エミュレーターではfunctions/.secret.localでキーを設定できます。モデル・キー未設定なら設定が必要というエラーを表示し、AIとして定型文を返しません。今回の作業ではキー設定・外部AIへの実データ送信・本番配備は行っていません。
