# 課題提出・確認の開発デモ

新仕様の中心は「先生が課題を配布 → 生徒がテキスト提出して30コイン → 先生が承認して70コイン → ショップ購入」です。

## 起動と操作

`flutter run` のデバッグ実行では、先生・生徒の切り替えを使うローカルデモが起動します。

1. 先生を選択して「確定」。動物園の「課題」から「課題を作成」。科目・タイトル・説明・締切を指定して配布します。
2. 動物園に戻り「その他 → 先生・生徒を選び直す」で生徒に切り替えます。
3. 「課題 → 詳細・回答する」で回答を入力して提出。初回のみ30コインが増え、確認待ちになります。
4. 同じ操作で先生に切り替え、「課題 → 提出内容を確認」で回答・提出日時を確認します。
5. コメントを入力し「内容を確認して承認」、または「再提出を依頼」を押します。
6. 再提出依頼の場合、生徒はコメントを見て再提出できます。再提出の追加報酬はありません。承認報酬は一度だけ70コインです。
7. 生徒の動物園に戻ると残高を確認できます。「その他 → ショップ」で100コインのウサギを購入できます。

## データと制約

- `DemoAssignmentStore` が課題、課題×生徒ごとの提出、報酬台帳を管理し、既存のゲーム・ショップに確定状態を渡します。
- デモクラス1つ、生徒1人（架空の「デモ生徒」）です。先生と生徒のデータは画面を戻っても維持されます。アプリ再起動時には消えます。
- 回答は空白のみ不可、5000文字以内。コメント1000文字、課題名100文字、説明3000文字までです。
- 期限後提出を許容し、期限後と表示します。再提出回数と確認日時を保持します。承認済みは変更できません。
- 報酬キーは課題ID・デモ生徒ID・報酬種別で一意。同期処理で提出状態と報酬を更新し、同じ提出・承認の再送でも重複付与しません。
- デモを本番の認証・権限検証と見なしてはいけません。ロール選択は認証ではなく、端末内メモリは信頼できるサーバーではありません。
- デモはデバッグビルドでのみアプリに接続します。リリースビルドでは無効です。
- Firebase Authentication / Firestore / Cloud Functions は未接続。別端末への配布、永続保存、塾・クラス単位の認可は未対応です。
- 本番には認証されたUIDと所属情報、Security Rules、サーバートランザクションによる提出・承認・報酬の原子的更新が必要です。

## 検証

`flutter analyze` と `flutter test`。課題作成、ロール切り替え、提出・再提出・承認、報酬の二重付与防止、購入への残高連携をテストします。既存の外部結果受信用モックは別途注入するテスト用途として維持しています。
